# CILica and cached FFS reads, 2026-11-08

This follows the [HDD/cached-read investigation](kickstart-ffs-hdd-cached-followup-2026-11-07.md).
The reference is the earlier FFS HUNK
`45D6AC27C6F1C48227606D3A4A2B6BFE5105DFBB1C100FAB0FDBCF46376CD1A6`.
The target is the remaining cached 4 KiB Fast RAM/CF deficit, with HDD results
checked separately at all four request sizes and both cache policies.

## CILica activation

CopperSharp SDK native builds enable restricted CILica preprocessing by default.
CopperFS's standalone build invoked the compiler CLI directly, so that SDK stage
was bypassed. Build-Handler.ps1 now invokes CopperSharp's optimize-il.ps1 before
native compilation. The original DLL stays in inputs; the rewritten DLL and
its .cilica.json report stay in cilica. SkipCilica is an explicit diagnostic
opt-out. An optimization failure aborts the build. Native managed intermediates
are isolated under each artifact root to avoid concurrent Rebuild collisions.

The frozen toolchain starts at CopperSharp68k commit
`c156ad8641413eec725b4e01a7f93e896bce033d`, with 1,304 compiler/SDK/vendor source
files retained under artifacts/ffs-cilica. Restricted CILica is pinned to
`a879c85f1608c764c7ab4f52b66b2b5db1ee60b6`. Reports verify
AssumeLittleEndian=false, AllowCrossAssemblyIPO=false and VerifyEachPass=true.
Only the handler module is rewritten; dependency assemblies remain original,
matching the SDK's restricted pipeline. The initial FFS pass reports 247
optimized methods out of 338 candidates.

The initial CILica-only FFS code grows from 181,144 to 215,052 bytes. Its
diagnostic 4 KiB result changes negligibly; the 30-byte copy loop still costs
about 3.95 million cycles. Code size and an optimization report alone do not
establish a throughput improvement.

## Native read path

The FFS-only dispatcher tests a complete cached read before entering the general
read decoder. The combined path validates the owned file, cursor, full run,
payload window, output mapping and overlay precedence, performs the existing
copy, then completes the packet. Disjoint file/packet/state spans permit
reloading completion arguments after copying, reducing their live ranges.
Aliases, misses, EOF, bypass and non-FFS formats retain the original reader.
The ownership traversal retains its existing 4,096-object boundary. New native
tests cover that boundary and a read destination aliasing packet arguments.
No mount/file records, cache budgets, copy kernel or read-ahead thresholds change.

## Compiler investigation

CILica inlining exposes a 108-byte dispatch frame, compared with 12 bytes in
the reference. The generated entry clears include scratch needed by other
packet paths. This causes a recurring cost even on read packets. The FFS
build now keeps the Smart read/enumeration helper out of line; the common
dispatch frame falls to zero bytes. This is a C# source boundary restricted
to the existing FFS build flag, preserving its fallback behavior.

CopperSharp68k's private initialization analysis now starts its backward
must-analysis at the greatest fixed point. An unrelated cycle cannot pin
initialization of private bytes overwritten before any observation. Reads,
escapes, GC references, exception handlers and dynamic stack storage retain
their conservative handling. Tests exercise a pure unobserved loop, a loop
followed by a full write, and reads/escapes inside a loop. The final handler
uses the frozen compiler baseline plus this change; concurrent compiler
development in the working checkout is excluded from its provenance.
Code-generation changes belong in CopperSharp68k; no generated bytes, ROMs,
original handlers or device timings are patched.

Cached Fast RAM/CF 4 KiB changes from 461.30 to 467.80 KiB/s on Kickstart 3.0,
and 461.66 to 468.15 on 3.1. Matched original FFS rates are 490.32 and 490.72.
This improves throughput about 1.4% and reduces the original-handler deficit
from 5.9% to about 4.6%; it does not close the gap. The diagnostic read phase
falls from approximately 15.28 to 15.08 million cycles, while the payload copy
still consumes approximately 3.95 million.

HDD session results are mixed against the preceding Copper snapshot. Cached
4 KiB ranges from 0.994 to 1.021 times its earlier throughput; 64 KiB ranges

by 7,520 cycles, but time outside that phase increases by 113,360 cycles.
The separate open profile attributes only about 1,000 extra instruction cycles;
the rest is consistent with synthetic media/guest scheduling, rather than
additional payload commands. This is evidence of a session regression, not a
claim of a uniform HDD nonregression. The strict HDD requirement remains open
for this candidate. Original controls retain matching input identities, with
up to 1.72% session-time variation across runs; the reproduced control above
is reported separately instead of dismissing the regression as noise.

Both cache policies retain matching small-read command/byte/PIO/completion

These shared-source edits were preserved and tested rather than overwritten.

Ranges combine Kickstart 3.0/3.1. Cached Fast RAM/CF 4 KiB is now 467.75 and
468.09 KiB/s, versus starting Copper 461.30/461.66 and matched original
490.37/490.82. The throughput gain is about **1.4%**, with a remaining original
deficit of **4.61–4.63%**. Its diagnostic read phase takes 15,069,780 cycles;
the unchanged copy still consumes 3,950,373 cycles. The optimized dispatcher
reduces overhead around that copy rather than replacing the extra payload copy.

The open/close separation recovers the prior Fast RAM/HDD 512 B and 64 KiB
regressions. Every HDD 64 B/512 B workload and every HDD 4 KiB bypass workload
improves against starting Copper. Cached stock 4 KiB still regresses: 416.28
to 415.87 KiB/s on 3.0 (**−0.10%**) and 418.56 to 415.29 on 3.1 (**−0.78%**).
Stock 3.1 cached 64 KiB changes from 562.40 to 561.29 (**−0.20%**); its bypass
counterpart changes from 562.41 to 561.82 (**−0.10%**). Other HDD 64 KiB
configurations improve. Thus the strict requirement of no HDD regression is
**not achieved**, although every latest HDD comparison still beats original FFS.
This is a measured partial optimization, not a claim that the gap is closed or
that all acceptance criteria pass.

A further C# grouped-load copy experiment, with a narrow CopperSharp store-group
extension for postincrement loads, was rejected. It passed 55 focused semantic
tests, but register placement broke the desired grouping in the real C# kernel.
At 4 KiB the CILica probe needed 7,607 rather than 4,627 68020 instruction cycles
and 35,298 rather than 22,876 on 68000. Neither that copier nor the experimental
compiler change remains in maintained source. The retained compiler change is
the private initialization fixed point described above. The next useful copy
work needs evidence for register allocation/coalescing before another kernel is
adopted; an unroll alone has repeatedly failed.

Concurrent subsequent SFS2-only cache-construction edits remain in the working
checkout and are outside this frozen FFS benchmark source receipt. No benchmark
record or previously published artifact was overwritten.
