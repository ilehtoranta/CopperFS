# Storage matrix implementation and validation, 7 November 2026

The original-SFS IDE mount diagnosis below is superseded by the
[partition-fixture investigation](kickstart-sfs2-ide-mount-fix-2026-11-07.md).
The historical flat fixture selected a whole-device geometry path; a correctly
described partition mounts through the unmodified ROM. Historical raw records
remain immutable. Protocol v2 requires successful original-handler reads.

The [protocol](kickstart-storage-matrix.md) adds opt-in timed CopperHDF and native
read-only Gayle IDE alongside the original synchronous backend. Device timing,
ATA, native guest interrupt entry, probe, runner and reporting are C#. Guest
completion code is generated by CopperSharp68k; no compiler change was required.
The portable filesystem change adds diagnostic `scsi.device` payload-bypass
control `0x43504302`, retaining the existing CopperHDF control and normal caching.
Scenario selection, manifest creation, execution and reports live in the C#
runner; PowerShell forwards arguments. Twelve BCL-only option tests and a separate
six-case CLI smoke run pass without changing the frozen full-matrix harness.

## Full-ROM matrix

The final-build matrix completed under `artifacts/storage-v1/full-matrix-v5/`.
The complete matrix accounts for 1,188 scheduled attempts and 99 successful case
receipts: 1,092 validated read workloads and 96 unavailable original-SFS IDE
attempts. Those receipts represent 91 read cases and 8 capability-failure cases;
the unavailable attempts are not successful read benchmarks. Earlier partial
development runs are explicitly excluded. The final
report validates every returned payload and unchanged read-only media, records
actual PIO bytes with CopperHDF absent for IDE, and compares policies only within
matching machine/ROM/device configurations.

The accepted reads validate 631.3125 MiB of returned payload. All 99 matching
64-byte cached/bypass trial pairs retain identical read-command counts. Report
revalidation passes without rewriting existing output. Negative checks reject
changed payload hashes, missing receipts, differing existing reports and attempts
to reuse an execution directory. The source receipts match 54 engine files,
11 harness files and 2 executor files against their compiled PDB hashes.

The complete local outputs are [report.md](../artifacts/storage-v1/full-matrix-v5/report.md),
[summary.csv](../artifacts/storage-v1/full-matrix-v5/summary.csv),
[measurements.json](../artifacts/storage-v1/full-matrix-v5/measurements.json) and
[unavailable.json](../artifacts/storage-v1/full-matrix-v5/unavailable.json).

The preliminary cold 4 KiB qualification run completed all 99 cases: 91 validated reads
and 8 confirmed unavailable original-SFS IDE cases. Original SFS 1.279 requests
`TD_GETGEOMETRY` (22); the unmodified 39.106 ROM's dispatch table rejects it with
`io_Error=-1`. The handler then clears its device size and refuses the mount
with DOS error 225 before filesystem reads. A separate native C# device request
captures the rejected geometry command for every unavailable trial. No original
IDE SFS throughput or relative ratio is reported. The native FFS and Copper IDE
paths remain measurable. This is an unavailable comparison, not a successful
read test or a missing media input.

Fresh-machine trials open the volume directly. The legacy probe's inhibit/remount
pair remains for legacy invocations; applying it during original SFS asynchronous
startup caused a race in the development harness. The generated completion
server also explicitly loads SysBase because Exec interrupt-server A6 is scratch.
Regression tests exercise that ABI and the pending node type of reused change
registration requests.

The previous development HDD results are excluded. A regression test exposed
abandoned speculative entries pinning the drive cache after a stream redirect:
only one of four read-ahead slots remained usable. The corrected C# policy makes
old speculative entries replaceable, retains cache hits until replacement and
protects unread foreground data in its separate sector buffer. The new test fails
before the fix and passes afterward; the complete diagnostic suite and zero
steady-state allocation checks pass. The complete matrix uses one corrected build.

The full report also includes the TRST build and the historical zero-latency
control. Policy preference depends on the matched backend and memory profile:
for stock FFS 4 KiB reads, bypass improves zero-latency throughput, whereas cached
reads improve native IDE HDD throughput. The corrected timed-HDD original FFS
baseline is 578.09 KiB/s, replacing the excluded development result.

The synthetic HDD/CF timings are not physical measurements. Gayle's conservative
bus wait policy and unverified AA electrical details remain explicit in every
configuration record. Fast RAM denotes verified placement in the engine's Fast
region; the existing EC020/memory bridge is not a calibrated physical A1200 model.
No packages, ROMs, media or historical benchmark records
are published or replaced.
