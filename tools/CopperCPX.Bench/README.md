# Native CPX4 comparison

This tool boots the same guest workload under the CPX4 HUNK, original Kickstart
FFS 40.1 and SFS 1.279. It records emulated bus cycles separately for mutation,
explicit flush, remount and complete read/verification. It checks persisted CPX4,
FFS and SFS payloads independently of the guest. Failed checks produce a nonzero
exit status. Inputs and outputs are hashed in `benchmark.json`.

The machine is a 68020 with 512 KiB Chip plus 2 MiB Fast, 16 MiB hardfiles,
512-byte sectors and 32 requested DOS buffers. CPX4 uses its fixed internal
arenas independently of that setting. Handler code may target 68000. Two trials
per handler run in order CPX4, FFS, SFS, SFS, CPX4, FFS. This is a RAM-backed
emulator-device comparison, not a physical-disk throughput measurement or an
equal-durability assertion about the original handlers.

Provide your licensed ROM and original binaries. No ROM or original handler is
downloaded or supplied. The SFS input must be a clean, formatted 16 MiB SFS 1.279
image with no `Bench` directory. CPX4 and FFS images are generated by the tool.
Source fixtures and bootstrap follow the existing MIT-licensed repository tests.
The CopperSharp68k and CopperScreen sibling workspaces are required, like the
existing native instruction tests. There is no CopperStart project dependency.

From the repository root in PowerShell:

```powershell
$env:CPX_BENCH_ROM = '<Kickstart 3.1 ROM path>'
$env:CPX_BENCH_FFS_HANDLER = '<original FFS 40.1 HUNK path>'
$env:CPX_BENCH_SFS_HANDLER = '<original SFS 1.279 HUNK path>'
$env:CPX_BENCH_SFS_IMAGE = '<clean formatted SFS 16 MiB image path>'
$env:CPX_BENCH_HANDLER = '<CPX4 HUNK path>'
$env:CPX_BENCH_ROOT = '<fresh output directory>'
dotnet run --project tools/CopperCPX.Bench -c Release -- mixed
```

Use `stream` for 32 writes of 64 KiB (2 MiB), followed by partial overwrites,
namespace operations, flush, remount and full verification. Mixed uses an 8 KiB
initial write, two partial overwrites and truncation to 6003 bytes. Streaming
buffer initialization precedes timing; mixed retains the original test sequence,
including initialization. The benchmark guest's byte-checking loop dominates
streaming verification time, so inspect mutation and flush separately too.

`CPX_ONLY=1` runs a single development trial and writes its `result.json`, without
the aggregate comparison. The external inputs are still required. Use a fresh
output directory for each run. Generated hardfiles and binaries stay in ignored
artifacts; do not commit or publish them.
