Build the handler

Install .NET 10 and place a CopperSharp68k checkout beside CopperFS. From the CopperFS root, build the standalone Amiga handler and the optional maintenance command.

./build/Build-Handler.ps1 -Ffs -ArtifactRoot artifacts/ffs
./build/Build-Trim.ps1

The handler is artifacts/ffs/CopperFFS. The default CPU is the 68000. Use -Cpu 68020 for a 68020 build or -CopperSharpRoot to select another toolchain checkout. Repository build instructions.

Manual TRIM

Install the matching CopperTrim command in C: and the handler in L:. On a writable DOS0 or DOS1 mount, substitute your volume name for DH0:.

CopperTrim DH0: CHECK
CopperTrim DH0: DRYRUN
CopperTrim DH0:

CHECK queries device support. DRYRUN flushes pending changes and reports free ranges. The final command issues SCSI UNMAP for verified free space. The device and bridge must support UNMAP through HD_SCSICMD. CopperTrim command reference.

Compatibility results

Kickstart 3.1 comparisons with FastFileSystem 40.1 exercised DD and HD floppy images and 16 MB hard disk images for both OFS and FFS. Each of the six cases passed independent content checks after writing and reopening the image with both handlers. Full-ROM comparison matrix.

The report identifies the tested binaries and records host and compiled-native replay results separately. Physical-drive behavior remains unqualified by these emulator runs. Validation coverage.
