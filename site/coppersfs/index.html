CopperSFS

An Amiga handler for Smart File System volumes, including the updated SFS2 format.

On this page Current source SFS preview.4 Test coverage

Current source

The default SFS and SFS2 handlers use a TRST redo journal. On mount, the handler replays complete journal records before making the volume available. Compatibility and recovery.

Disk formatTRST support
SFS (SFS\0)Supports buffered writes and replays records in the original SFS journal format.
SFS2Uses a 192 kB staging area when writing changes.

Build a standalone handler

With .NET 10 installed and CopperSharp68k beside CopperFS, run the command for your volume. Each directory receives a handler named CopperSFS.

./build/Build-Handler.ps1 -ArtifactRoot artifacts/sfs
./build/Build-Handler.ps1 -Sfs2 -ArtifactRoot artifacts/sfs2-trst

The default target is the 68000. Add -Cpu 68020 for a 68020 or later CPU. Source build instructions.

SFS preview.4

The v0.1.0-preview.4 release supplies binaries for an existing SFS\0 partition. Its default 68020 handler uses buffered writes and a 256 kB clean-data cache. The 68020 package also offers strict writes and other cache sizes. Select the separate 68000 package for a 68000 or 68010.

Before switching handlers, confirm a successful filesystem ACTION_FLUSH or clean inhibit. After an interrupted update, recover the volume with the preview handler first. Preview durability and recovery.

Install on a test volume

Use an independently backed-up disposable partition, a separate boot volume and Kickstart 2.0 or newer. Verify the downloaded package checksums. Copy the executable for your CPU as L:CopperSFS, then adapt the supplied mount entry to the existing partition’s geometry, device, unit and DMA mask. Mount, write a test file, flush and verify its contents after remount. Package selection and installation instructions.

Test coverage

Source builds. The original-handler comparison exercised SFS and SFS2 TRST writes on 16 MB images. After a fix to SFS file replacement, all nine cases in the filesystem comparison passed. Correctness results and tested builds.

Published preview. The buffered 68020 binary was compared with SmartFilesystem 1.279 under Kickstart 3.1, including recovery and clean handoff. The 68000 binary received five smoke cases on the 68020 emulator profile. Full-ROM coverage on a 68000 and physical hardware qualification for that package remain open. Preview qualification by binary.
